# weread-exporter

微信读书全本导出工具 — 通过 Playwright + Canvas Hook 提取完整书籍**图文**内容，导出为 Markdown。文字与插图按阅读顺序精确交错。

## 原始仓库

本项目的原始仓库为：[lbq110/weread-exporter](https://github.com/lbq110/weread-exporter.git)。

## 原理

微信读书网页版用 Canvas 渲染书籍文字（而非 DOM 文本节点），插图则是 DOM `<img>` 元素。本工具：

1. **Playwright 自动化** — 启动 Chromium，持久化登录会话（扫码一次，后续复用）
2. **Canvas 文字坐标** — 拦截文字绘制和 Canvas 复制，按每块 Canvas 的实际位置、缩放换算为文档坐标
3. **DOM 字符层** — 同页目录锚点不重绘 Canvas 时，收集字符层并按坐标去重，不再把无关 Canvas 正文追加到目标小节
4. **精确章节边界** — 确认当前标题起点，支持分行标题，以及目录冒号在正文中替换为换行的排版（如“附录：方法索引”排成两行）；只按紧邻的下一目录标题切分，避免“附录”等短标题匹配到远处目录项
5. **图文排列** — 滚动扫描到下一节或当前内容末尾，收集下方图片，按文档坐标交错排列；保留分册标题前的封面图，同一图片可出现在不同章节
6. **完整性校验** — 校验目录顺序、文件编号和内容；只有实际确认起止边界的纯标题页可以没有正文，未定位内容不会保存

旧版本产物可能已有串章或漏图，修改代码后不会自动修正旧文件。需要重建时使用 `--restart`，旧产物会自动备份。

## 环境准备

请先安装 [uv](https://docs.astral.sh/uv/)，然后在项目根目录创建虚拟环境并安装依赖：

```bash
uv venv --python 3.13
uv pip install -r requirements.txt
uv run python -m playwright install chromium
```

后续命令统一通过 `uv run` 执行，无需手动激活虚拟环境。

## 使用

### 1. 导出书籍（文字 + 图片 URL）

**使用前请确保微信读书采用纵向（上下滚动）阅读模式。** 横向翻页模式可能导致目录跳转失败或正文缺失。程序会在读取目录前检查模式；如果检测到横向模式，请在程序打开的浏览器中，通过阅读器侧边工具栏的阅读模式切换按钮改为纵向模式。程序最多等待 2 分钟，切换后自动继续。

如果此前已经在横向模式下生成过断点，切换模式后建议使用 `--restart` 重新导出，避免目录中的“扉页”等差异导致断点不一致。纵向模式是运行前提，不代表正文完整性已得到保证。

```bash
# 传入 reader URL（推荐）
uv run export_precise.py https://weread.qq.com/web/reader/d31323b0813abaf26g0137c2

# 或直接传 book_id
uv run export_precise.py d31323b0813abaf26g0137c2

# 丢弃错误断点并重新导出；旧产物会先移动到 output/_backups/
uv run export_precise.py --restart d31323b0813abaf26g0137c2
```

- 首次运行会弹出浏览器要求扫码登录，会话自动保存在 `cache/browser_profile/`，后续复用
- 按目录位置逐项点击并验证 selected 下标，同名章节也能准确区分
- 页底短小节导致目录高亮滞后时，若唯一的目标标题完整可见，仍会提取并保存该节，再继续下一节；不会直接跳过章节
- **自动续传**：从磁盘上最后一个完整目录位置继续；损坏或越界断点会要求 `--restart`
- 新版产物已完整且通过校验时，再次运行会直接下载缺少的图片并合并，无需重开浏览器
- 只有目录覆盖和非空内容校验全部通过，才会合并并显示“全书导出完成”
- 图片此阶段只记录 URL，单章 Markdown 用 `../images/chXXXX_imgNN.jpg` 引用图片，全书 Markdown 用 `<book_id>/images/` 引用

### 2. 下载图片

```bash
uv run download_images.py d31323b0813abaf26g0137c2
```

- 从 `raw/*.json` 读取所有图片 URL，8 线程并发下载到 `images/`
- **强制 IPv4**：macOS 上 urllib 默认先试 IPv6，路由不通会每张图卡约 120 秒；强制 IPv4 后恢复秒级
- 已存在的图片自动跳过（可重复运行补齐失败项）

> 导出和下载分两步：翻页抓取时若同步下载大图会阻塞翻页，故先记录 URL、翻完后统一并发下载。

## 输出

```
output/
├── _backups/                 # --restart 时保留的旧书籍目录
├── <book_id>/
│   ├── _catalog.json        # 目录章节标题列表（用于判定全书末尾）
│   ├── chapters/            # 每章独立 Markdown（图文交错）
│   │   ├── 0001.md
│   │   ├── 0002.md
│   │   └── ...
│   ├── images/              # 下载的插图 chXXXX_imgNN.jpg
│   └── raw/                 # 每章的图片 URL 记录 + 字数
│       ├── 0001.json
│       └── ...
└── 书名.md                  # 合并后的全本文件（图片用 <book_id>/images/ 相对路径）
```

图片下载完成后，用 Typora / Obsidian 等打开全本 `.md` 即可查看图文。

## 限制

- 需要有效的微信读书账号，且对目标书籍有阅读权限（无限卡会员或已购买）
- 部分出版社限制网页端阅读（显示"去 App 阅读"），此类书籍无法导出
- 纯图廊章节图片密集时，图注与图的配对偶尔差一位；正文章节里图片相对段落的位置准确
- 导出速度受阅读器渲染和目录动画限制，长章节需要逐段滚动扫描，耗时随篇幅增加

## 工作流程

```
export_precise.py:
  浏览器登录 → 读取目录 → 精确点击下一个未导出目录项并验证
    → 按每块 Canvas / DOM 的文档坐标收集文字和图片
    → 确认标题起点 → 扫描到下一节或当前内容底部 → 输出章节 md
    → 目录顺序、文件编号、非空内容全部校验通过后合并全书

download_images.py:
  读 raw/*.json 图片 URL → 强制 IPv4 + 8 线程并发下载 → images/
```
